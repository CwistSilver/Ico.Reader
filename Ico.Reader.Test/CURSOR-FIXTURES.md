# Cursor fixtures to author

The ICO fixtures are generated by `Tools/generate-fixtures.ps1`, but cursors are not: **neither
icotool nor ImageMagick writes a real `.cur`**. Both were checked — asked for a cursor, each emits a
file whose type field still says `1` (icon) and whose hotspot fields hold the plane count and colour
depth instead of coordinates.

Patching those bytes afterwards does produce a spec-valid cursor, but it only ever produces cursors
shaped exactly like the icons the same tool wrote. Fixtures authored in a real cursor editor are
worth more: they carry whatever a genuine editor actually emits — its palette choices, its mask
generation, its per-image hotspots — which is what the library will meet in the wild.

Save the files below into `Ico.Reader.Test/Resources/Cur/`, then run:

```powershell
pwsh Ico.Reader.Test/Tools/verify-cursors.ps1
```

It reads the bytes rather than trusting the editor, and reports every file that is missing, saved as
an icon, or off-spec. Once it prints all green, the cursor test suite can be written against them.

## The files

Source artwork is `Ico.Reader.Test/Resources/sample.png` (256×256 RGBA). Reuse it for every entry so
cursor and icon fixtures stay visually comparable.

Three things matter more than the artwork:

- **The hotspots must be exactly these values.** They are deliberately asymmetric. A cursor with a
  centred hotspot would pass even if the reader swapped X and Y, or read the plane count as the
  hotspot — which is exactly the bug class these fixtures exist to catch.
- **The colour depth must be exactly as listed.** If the editor silently promotes a 4 bpp cursor to
  32 bpp, that row stops testing the 4 bpp decoder. The verify script checks this.
- **File 9 needs real mask transparency**, and files 1–8, 10, 11 should be fully opaque, so the two
  cases stay separable.

## Authoring in RealWorld Cursor Editor

Free, from [rw-designer.com](https://www.rw-designer.com/cursor-maker). Menu wording shifts a little
between versions, so treat the steps as the flow rather than literal labels — the table above is the
contract, and `verify-cursors.ps1` is the judge.

### A single-image cursor (files 1-9)

1. `File → New → Cursor`. In the new-document dialog set the canvas size (e.g. 32×32) and pick the
   colour depth for that row. If the dialog only offers 32-bit, create it anyway and change the
   depth in step 4.
2. Open `Resources/sample.png` in a second tab (`File → Open`), select all, copy.
3. Switch back to the cursor tab and paste. Scale the pasted layer to fill the canvas, then flatten.
4. Check the document's image-format list (the panel listing the formats in the document, usually
   docked on the left). It should hold exactly one format at the size and depth from the table. If
   the depth is wrong, right-click the format → change/convert it to the required bit depth, and
   delete any extra formats the editor added on its own.
5. Set the hotspot: pick the hotspot tool from the toolbar (crosshair), or `Cursor → Set hotspot`.
   Do not click it into place by eye — type the exact X and Y from the table into the hotspot
   fields. A one-pixel drift makes the fixture wrong.
6. `File → Save As`, choose **Windows Cursor (\*.cur)**, and use the exact file name from the table.
   Do not save as `.ico` and rename it; the type field inside the file is what matters.

### A multi-image cursor (files 10 and 11)

1. Start from the largest image (48×48) and author it as above.
2. In the image-format list, `Add image format` twice — once for 32×32 and once for 16×16, at the
   depths from the table. The editor will down-scale the existing artwork; that is fine.
3. Select each format in turn and set **its own** hotspot from the table. The hotspot is stored per
   image, and files 10 and 11 exist specifically to prove the reader keeps them apart.
4. Save once as `.cur` — all three images live in the one file.

### Shaping file 9

`cursor_32_8bpp_masked.cur` needs pixels that are genuinely transparent, so the AND mask has both
states. Erase the four corners (or the area outside a circle) with the eraser set to full
transparency before saving. In an 8 bpp cursor there is no alpha channel, so the editor writes that
transparency into the AND mask — which is the path under test. Keep the centre pixel opaque.

### Alternatives

- **Greenfish Icon Editor Pro** (free) — same flow: `File → New → Cursor`, set the hotspot from the
  `Cursor` menu with numeric entry, and use the frame list to add sizes.
- **Visual Studio's image editor** can write `.cur` and set a hotspot, but it is awkward about colour
  depth; if you use it, lean on the verify script.
- **Axialis CursorWorkshop** (paid) has the most precise depth and hotspot control if you already
  own it.

Whatever you use, the verify script is the acceptance test.

## Replacing or extending the set

The fixtures are in place and `Integration/CurReadTests.cs` runs against them. If you re-author a
file or add one:

1. Save it into `Resources/Cur/` and run `Tools/verify-cursors.ps1` until it is green. Add a row to
   the `$Expected` array in that script for anything new.
2. Re-run `Tools/generate-fixtures.ps1`. It leaves the `.cur` files alone — they are hand-authored —
   but re-extracts their reference pixels into `Resources/Expected/` and recompiles the PE fixture.
3. Add the file to `Infrastructure/CurFixtures.cs` so the theories pick it up.

`Resources/Pe/Fixtures.rc` is generated, so change the `$rcLines` array in
`Tools/generate-fixtures.ps1` rather than the `.rc` itself. Three cursors are embedded there today
(`cursor_32_32bpp`, `cursor_multi`, `cursor_16_8bpp`), giving the PE fixture its `RT_CURSOR` and
`RT_GROUP_CURSOR` resources.

## What these fixtures caught

Two defects, both fixed:

- `ImageReference.FromIcoDirectoryEntry` never set `ImageReference.IcoType`, so images from a
  standalone `.cur` reported `IcoType.Icon`. Only the PE path assigned `Cursor`.
- `RT_GROUP_CURSOR` directory entries store width and height as **words**, with the height doubled
  to cover the AND mask; an `RT_GROUP_ICON` entry uses two **bytes**. Both readers used the icon
  layout, so every cursor read out of a PE reported `Height = 0`, and any cursor wider than 255px
  would have had its width truncated.
